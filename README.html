compaction-guard

Before an AI agent squeezes its memory, this saves an exact copy first. If the copy fails, the squeeze doesn't happen.

For Claude Code. One file, no dependencies, Node.js 18 or later.

Full details: README.mdLicense: FSL-1.1-MITVersion 0.1.0

What happens at every compaction

Claude Code is about to compact. First:

  1. Save a copy of the whole conversation (again, if it changed while copying)
  2. Read the copy back and match its fingerprint (SHA-256)
  3. Write a receipt
✓ All three workedCompaction goes ahead.
Block the compactionWhen any step fails. Nothing is lost, and you see why.

Where the copies go

~/.compaction-guard/
  index.jsonl                  ← one receipt per copy
  <project>/<session>/<time>-<manual|auto>-<random>.jsonl

Private to you: folders 0700, files 0600 on macOS and Linux.

Check the copies, and get one back

verify: is every copy still exact?

Re-hashes every copy and lists any that are missing or changed.

node compaction-guard.mjs verify

restore: put a copy back

Checks the copy against its receipt first, then writes it. Never replaces a file unless you add --force.

node compaction-guard.mjs restore <receipt id> --to ~/restored

Know this before you install

  • A blocked automatic compaction can fail your request. Usually the disk is full or the folder is locked. Fix that, or set COMPACTION_GUARD_FAIL_OPEN=1.
  • Copies hold whole conversations, secrets included. Keep them on your machine. Never sync or commit them.
  • Nothing is deleted. Every compaction adds a copy.
